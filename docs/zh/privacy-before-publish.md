# 公开前的隐私与版权自检

旅行 App 天然装着很多私人信息：谁和谁去、住哪、哪天在哪、订单、证件、服务器地址。本模板本身不含任何真实旅行数据；但你用它做自己的 App 时，仓库会逐渐装满这些信息。建议：

- **你的旅行仓库保持私有。** 需要分享给朋友时，分享 TestFlight，而不是仓库。
- 想把改进贡献回模板，或公开自己的版本，先按本文检查。

## 1. 永远不要提交的东西

| 内容 | 放在哪里 |
| --- | --- |
| Apple Team ID、你自己的 Bundle ID | `ios/Signing.xcconfig`（已忽略） |
| 后端地址、共享密钥 | `ios/SharedAccess.xcconfig`（已忽略） |
| 生成的 Xcode 工程（会记录 Team ID） | `ios/*.xcodeproj`（已忽略，用 `xcodegen` 生成） |
| APNs `.p8` 密钥、服务器环境变量 | 只放在服务器上，例如 `/etc/trip-journal*.env` |
| 数据库、备份、门票原件 | 服务器或本机私密目录 |
| 证件号、订单号、确认号、手机号、住址 | 不写进任何文件；门票原件只在 App 内保存 |

## 2. 容易漏掉的私人信息

- 真实姓名、昵称、情侣称呼；GitHub 用户名、邮箱。
- 出发城市、家附近的机场；航班号 + 日期（组合起来能定位到人）；实付金额。
- 本机路径（含用户名的主目录路径）、外置硬盘路径、设备名称。
- 服务器 IP、域名、秘密路径、端口；App Store Connect 的应用 ID、构建 UUID。
- 过程记录里的截图、日志、回执（常常夹带上面所有东西）。
- 测试用的口令、示例账号（不要用生日、出发日期之类的真实数字）。
- **Git 历史**：删掉文件不等于删掉历史。私有仓库转公开前，最稳妥的做法是用干净的新仓库重新提交需要公开的文件（本模板就是这样产生的），而不是在旧仓库上删改。

## 3. 版权与授权

| 素材 | 公开仓库中的做法 |
| --- | --- |
| 社交平台帖子（小红书等）的图片和正文 | 没有作者授权就不要放；只保留标题、作者、链接和你自己写的摘要 |
| 酒店 / 订房平台图片、报价截图 | 不要放 |
| 官方网站图片（标注 All Rights Reserved） | 不要放 |
| 开放许可照片（Wikimedia Commons 等） | 可以，必须保留作者、许可证和来源；CC BY-SA 的裁剪/缩略图是演绎作品，同样需要署名并按相同方式共享 |
| OpenStreetMap 数据 | 可以，注明 © OpenStreetMap contributors（ODbL） |
| 你自己拍的照片、自己写的文字 | 可以，建议明确许可证 |

## 4. 自动检查：`scripts/privacy_check.py`

脚本扫描所有会被发布的文件（已跟踪 + 未忽略的新文件），可选扫描全部 Git 历史：

- 内置规则：私钥、常见 API Token、本机路径、公网 IPv4、邮箱地址、超过 1 MB 的文件（`docs/assets/` 下的 README 图片放宽到 3 MB）。
- 你的私人词表：在仓库根目录建 `.privacy-denylist`（已被 git 忽略），每行一个正则，写上你不希望出现的字符串：

```text
# 名字、昵称、用户名
张三
zhangsan
# 城市、航班、日期
上海
MU ?1234
2031-04-
# 服务器与账号
my-domain\.com
203\.0\.113\.7
ABCDE12345
```

运行：

```bash
python3 scripts/privacy_check.py            # 工作区
python3 scripts/privacy_check.py --history  # 连同所有提交历史和提交作者
```

输出 `PASS` 再公开。脚本只能发现你告诉它的东西和常见模式；最后请自己通读一遍 `git diff`、文档和图片。

## 5. 提交身份

公开仓库会暴露每个提交的作者名和邮箱。建议使用 GitHub 提供的 noreply 邮箱（`<id>+<用户名>@users.noreply.github.com`），在仓库内设置：

```bash
git config user.email "<id>+<用户名>@users.noreply.github.com"
```
