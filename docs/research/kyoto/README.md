# 京都 3 日示例是怎么做出来的

`content/` 里的京都示例用来演示这个模板，也用来验证仓库自己的调研方法：**全部内容由 AI Agent 按 [research-playbook.md](../../zh/research-playbook.md) 调研、填写、校验**。本目录是完整的调研记录，任何一条信息都可以在这里找到来源和核对过程。

两道门禁都通过：`verify_content.py`（结构）与 `verify_content.py --require-complete`（不允许示例文字、占位链接和「待核实 / TODO」）。

## 过程与用时

2026-09-24，在 Claude Code 里完成：

1. **并行调研（约 41 分钟）**：4 个子 Agent 同时工作，各自读仓库的内容结构说明和调研手册，只写自己负责的文件：
   - 地点与坐标：约 104 个页面，另有约 40 次 OpenStreetMap 查询；
   - 照片：逐张打开 Commons 文件页核对许可证、作者、日期和分辨率，排除有水印、地点不符、日期不可信的图；
   - 餐饮：约 45 个页面，菜单与价格只取餐厅自己的页面，**没有打开任何订位系统**；
   - 行前准备、短句、实用信息、汇率：约 44 个页面，只引用官方页面。
2. **整合（约 15 分钟）**：主 Agent 按地点和餐厅的开放时间、定休日排出 3 天行程，写了 2 篇原创攻略，下载并压缩照片（下载前经人工确认清单），跑通两道门禁。

全程没有预订、付款、登录或提交表单。所有信息核对于 2026-09-24；2027 年的开放时间、票价和规则可能变化，**出发前请以官方最新页面为准**。

## 已知的未决事项（摘要）

- 清水寺 2027 年秋季夜间特别拜观日期、天龙寺法堂平日是否开放、MICHELIN 2027 名单（2027-02-16 公布）都要到时再核对。
- 部分日本官方页面对自动浏览器不开放，调研时读的是 Internet Archive 存档，JSON 里引用的是原始官方网址；公开使用前建议人工再打开一次。
- 餐厅中有两家的价格官网未注明是否含税，标为 `unknown`；一家小吃官网未公布价格，价格留空。
